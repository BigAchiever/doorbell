The Problem Every Tunnel Has

You close your laptop. Stripe fires a webhook. It gets a 502, and you go re-send it by hand from their dashboard. ngrok, frp, bore, chisel and Cloudflare Tunnel all drop it.

Doorbell holds it.

doorbell 3000        →  https://…/t/shop/
^C                   →  laptop closed
3 webhooks arrive    →  202 Accepted, held   (not 502)
doorbell 3000        →  all 3 delivered, in order

Any held request can also be replayed on demand — a feature ngrok charges for.

Try It Against This Gateway

go install github.com/danishalisiddiqui/doorbell/cmd/doorbell@latest

export DOORBELL_GATEWAY=…
export DOORBELL_TOKEN=<ask the operator>
doorbell 3000

No Go? Prebuilt binaries for macOS, Linux and Windows are built by make release.

Why This Needs Zerops

A tunnel is one long-lived TCP socket held open for hours. A serverless function sleeps between requests; when it sleeps the socket dies and the tunnel dies with it. This is not “harder on Vercel” — it is not expressible there.

What a tunnel requires, and which platforms provide it
RequirementZerops Vercel / Netlify / Workers
Raw TCP port Yes, 10–65435No — HTTP only
Always-on process Yes, no scale-to-zeroNo
Private network to DB & cache Yes, VXLANNo

Honest caveat: this would also run on Fly.io or a $5 VPS. What neither gives you is the whole network — gateway, Postgres, Valkey, private networking, managed TLS — standing up from a single pasted file in about 90 seconds.

Deploy Your Own

  1. Copy zerops-import.yml from the repository.
  2. In app.zerops.io, choose Import a project using YAML template and paste it.
  3. Wait about 90 seconds.
  4. Open the raw TCP control port: gw → Public access → port routing, public 7000 → internal 7000, protocol tcp.

That file is the product: ngrok is a SaaS you rent, this is a network you own.
